# 分段、话题交接与撤回窗口

## 分段设置

设置保存在选中的 AstrBot 原生配置 `platform_settings.segmented_reply` 中。页面记住选中的配置，刷新、重新读取、保存和后续编辑均使用该配置。配置选择只是编辑目标；消息实际使用哪个配置仍由 AstrBot 的会话配置分配决定。

| 控件 | 行为 |
| --- | --- |
| 仅对模型结果分段 | 提示主模型按完整意思自行分段，用空行表达段落。关闭时普通聊天不使用换行隔断。 |
| 启用分段回复 | 将模型段落拆成多条消息发送，适用于普通结果和缓冲后的流式结果。关闭时一条发送，模型段落是否保留由上一项控制。 |
| 第二句号 | 单独开启后，每段遇到第二个 `。` 才拆分；计数随分段重置。默认关闭。 |
| 启用分段词 | 单独开启后，按可编辑的词表细分。默认关闭。第二句号关闭时，词表中的第一个 `。` 就会拆分。 |
| 最多分几段 | 0 表示不限，1–20 表示最多文本段数；超出时合并相邻段，不截断回答。图片、语音等媒体保留顺序并遵循宿主发送约束。 |

模型段落和词表分段是两个层次。词表关闭、第二句号关闭时，不按标点强行细分。代码围栏内部保留换行和标点。官方 QQ、微信和钉钉等限制平台继续采用原生发送限制。

`guard_segments.py` 在事件的结果修饰钩子中准备 `Plain` 段；原生管线继续负责 TTS、长文本转图片和发送。三个细化字段编码在原生正则的 `at-guard-reply-v2` 注释中，正则本身对准备好的每个段落透传，避免再次断句。旧原生正则继续兼容；通过页面保存新控制项后进入新分段模式。

## 话题交接

判定放行只代表可以参与，并不保证事实完整。放行后将判定时同一会话的流水和当前输入作为临时材料交给主模型，保留发送者与时间顺序。主模型优先利用已有感知、记忆与图片观察；必要时使用实际可用工具补充，无法确认的事实应追问。

私聊、直接 @ 和判定放行共用上述理解要求。判定流水只注入一次，避免重复占用上下文。

`guard_evidence.py` 通过宿主 `on_llm_tool_respond` 收集成功查询的文字证据，写入有界短期记忆（最多256条、5分钟）。相同会话、发送者、人格和提供者配置下，查询词明确出现在当前问题时，最多复用两条、每条2000字符，作为临时资料注入；相关工具仍须出现在当前可用工具列表中。不同话题、不同用户、人格切换、过期、错误和写入/发送工具不复用。短期证据只在内存中，插件重载后清空；它减少重复查询动机，不强制拦截原生搜索工具，也不缓存完整回答。

稳定事实由主模型选择后调用现有 `memorize_long_term_memory` 等记忆工具，保存简明事实、来源和日期，继续通过统一身份、受众和隐私处理。时效内容需要过期重查。不能把判定理由、工具页面中的指令、模型推测或失败结果写为长期事实。不会另建一份绕过权限的长期向量库。

使用 LivingMemory 时须开启 `agent_tools.enable_memorize_tool` 并重载该插件，确认工具列表实际出现 `memorize_long_term_memory`；该工具的原默认值是关闭，仅有提示词不能完成长期写入。主模型是否调用、写入内容是否满足稳定事实条件仍需在实际消息中核对。

从绫配套改动：归档、作息、生成共用事件上的解析对象，只补一次媒体理解。当前事件的图片观察补回当前消息归档；旧归档没有批量更新。图片观察保留最多1200字符，按会话/用户/人格缓存一小时，最多256条，不读取旧的全局永久图片缓存。同源并发查询合并成一次。能力缓存保留各能力原有TTL（天气900秒、网页简介3600秒等），增加会话/用户/人格隔离与并发合并，缓存命中不占执行限流；无缓存TTL的写入类能力不合并。原生向量召回与长期记忆读取仍遵循原来的权限和新鲜度逻辑。

### 调用成本与降级边界

| 路径 | 本轮输入上限 | 新增模型调用 | 超时/降级 |
| --- | --- | --- | --- |
| 查询证据复用 | 最多2×2000字符和来源时间 | 0 | 5分钟过期；无明确主题命中则不注入 |
| 图片观察 | 最多1200字符/图 | 缓存未命中时沿用既有视觉调用 | 保留既有12秒媒体增强窗口；失败不缓存 |
| 工具能力 | 沿用能力参数、TTL和超时 | 不增加；同参数并发只执行一次 | 执行失败返回原有降级结果；不缓存失败 |
| 主回复 | 沿用当前主模型输出预算 | 不增加一次“理解模型” | 事实不足时查实际工具或追问；自主参与可静默 |

未进行真实模型生成或在线搜索质量实验，不能把离线通过解释为所有真实回答都必然贴题，也不能声称测出了线上token节省比例。

## 撤回窗口

收到原消息时绑定当前碎片批次。撤回通知只在该批次安静期截止之前有效，同用户续发会延长整个批次的截止时间。窗口内任何一条被撤回，整批不回复；已触发的取消在窗口结束后继续有效。窗口外的新撤回不会取消正在生成或打字中的回复。

碎片等待为0或私聊未开启碎片等待时，没有撤回保护窗口。撤回通知始终被拦截，不会作为新输入交给模型。

## 最近判定

分类覆盖最近保留的600条记录，筛选后最多展示100条，可与关键词搜索同时使用。

- 私聊：私人会话。
- 群聊 · 明确呼叫：明确呼叫机器人并进入判定的群消息。
- 公开发言 · 自主参与：群中未明确呼叫的参与候选。

原生直接 @ 的放行路径可能不调用判定模型，因此不会凭空生成小模型判定记录。旧记录缺少明确呼叫字段时按公开发言归类，详情保留原记录。
