# at_guard 与从绫配套运行

适用于本仓库增加 `gate_congling_prepare_compat` 后的代码，以及支持下述事件约定的
congling 配套实现。congling 为可选插件，不因安装 at_guard 自动安装或修改它。

## 解决的问题

普通自主回复受 `gate_reply_max_age_seconds` 限制，默认30秒。从绫读历史超过30秒时，
原总年龄检查会在正文生成或发送前丢掉当前回复，表现为“发了爬楼语，却没答当前问题”。
另一种原因是旧版从绫先爬楼、at_guard 后静默。这两种情况分别依靠耗时适配和钩子排序处理。

## 配套顺序与要求

```text
记录群消息与未读历史
  → at_guard 判断当前消息（on_llm_request 优先级10000）
  → 静默：停止当前请求，不爬楼，不消耗这批未读
  → 放行：从绫人格钩子（配套实现优先级9000）
      → 提示爬楼 → 读取历史 → 按独立设置决定是否补答历史
      → 同一请求注入历史摘要与人格 → 正常回答当前问题
  → at_guard 在模型返回和发送前复查有效期与新消息
```

AstrBot 请求钩子按优先级从高到低执行。从绫人格钩子需低于10000；
相同优先级也不能保证所需顺序。读历史失败应保留未读，不把旧摘要当成已成功阅读。
配套从绫按冻结的历史上界分块读全部遗留未读，当前触发消息不作为待补答历史；
阅读中到达的新消息留待后续批次。具体阅读、标记已读和补答逻辑由从绫维护。

从绫需在当前事件通过 `set_extra("congling:wake_prepare_seconds", seconds)` 上报
本次请求中实际爬楼/补课准备的秒数。建议用 `time.monotonic()` 测量，
在准备阶段的 `finally` 中记录，不能把正文生成耗时混进去。
at_guard 不凭版本号猜测这项能力，也不改写从绫的计时或会话版本。
仅更新 at_guard，不会自动修复旧版从绫先爬楼的行为或补齐它的计时上报。

## 对应配置页面

在 AstrBot 插件详情打开 at_guard 的 **guard** 页面，进入 **回复节奏**：

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| 从绫爬楼配套 `gate_congling_prepare_compat` | 开启 | 扣除当前事件有效的准备计时；关闭按原总年龄检查 |
| 回复机会有效期 `gate_reply_max_age_seconds` | 30秒 | 仍限制自主回复的等待、判定、正文生成与发送 |

保存即生效，不需要重载。参数手册可搜索“从绫”，字段旁也提供用途和例子。
状态说明显示“未检测到”“已安装但未启用”“钩子顺序符合”“早于或等于闸门”
或“顺序无法确认”。状态来自已加载插件元数据；“顺序符合”仍须当前事件实际上报计时。
刷新状态不会修改从绫的设置。

从绫的 **fromling** 页面及 AstrBot 原生配置有以下独立设置：

| 从绫设置 | 作用 | 配套建议 |
| --- | --- | --- |
| `night.crawl_enabled` 爬楼机制 | 阅读遗留未读；可发送爬楼提示 | 要读取历史时开启 |
| `night.rollup.enabled` 启用醒后补课 | 阅读后筛选并补答历史消息 | 按需要开启；默认关闭，只读历史不必开启 |
| `compat.at_guard_coupled` 醒后补课耦合 at_guard | 将补课候选评分交给 at_guard | 希望统一补课评分时开启；不控制钩子顺序或准备计时 |

在支持该流程的从绫实现中，爬楼与补课都关闭会保留未读；只开启爬楼则读取背景，
不补发历史回复。只开启补课也会读取历史，但不因关闭爬楼而发送爬楼提示。
本页开关只改变有效期算法，不会开启或关闭上述三项。

## 耗时规则与保护

```text
有效已用时间 = 收消息后的总时间 - 当前事件有效的准备时间
有效已用时间 > 回复机会有效期 → 取消自主回复
```

有效计时必须能转为有限数值，且在0至事件实际年龄之间；负数、布尔值、
NaN/无穷大、转换失败或超过总年龄的计时一律不扣除。
无从绫、未启用、旧版未上报、缓存摘要没有本次准备耗时，都不会凭空延长有效期。
计时不跨事件复用。

默认30秒时：

| 总耗时 | 有效准备时间 | 有效已用时间 | 结果（没有新消息） |
| --- | --- | --- | --- |
| 60秒 | 45秒 | 15秒 | 当前回复可继续 |
| 80秒 | 45秒 | 35秒 | 取消过期回复 |
| 60秒 | 未上报或关闭配套 | 60秒 | 按原规则取消 |

出现新群消息导致会话版本改变时，即使扣时后尚未过期，也取消旧自主回复。
模型返回与最终发送前均复查，避免读历史后拿过时上下文继续发言。
显式 @、称呼、唤醒命令沿用原直接呼叫规则，不新增自主回复限制。
闸门 `off` 仍完全解耦；观察模式不能作为“静默必不爬楼”的验收模式。
这项适配不会增加判定预算、清除新消息版本，或缓存是否回复。

## 验收与排查

1. 更新两个插件到满足事件约定的配套代码，重载后在 guard 查看从绫启用状态和顺序。
2. 保持 `gate_mode=enforce`，准备同会话未读历史，在测试会话触发普通消息。
3. 静默时不应由该请求发送爬楼语，历史仍留待后续放行；放行时应先爬楼再处理当前问题。
4. 准备耗时较长但有效已用时间未超过窗口时，当前答复应能继续。正文超时仍应取消。
5. 生成期间出现新群消息时，旧自主回复应取消；不是补发历史评论或强制每条消息回复。
6. 关闭“从绫爬楼配套”，同样的长准备请求应恢复原总年龄规则。

若仍“只爬楼没回复”，检查闸门判定原因、`_at_guard_delivery_blocked`、
从绫流程异常及是否真实上报当前事件计时。
`context_changed` 表示新消息撤销；`message_expired` 表示有效已用时间超窗。
从绫出现发送结果未知时按它的防重复规则人工核实，不应绕过后自动重发。
不要仅增大有效期掩盖顺序或正文生成失败。

## 回退与验证

关闭 `gate_congling_prepare_compat` 即回退到原有效期算法；该开关不改数据库或已读标记。
需要回退代码时恢复部署前的插件备份并重载；先前成功阅读的历史不因回退自动变回未读。

本仓库离线测试包括合法/无效计时、边界、开关、事件隔离、新消息撤销、
模型返回与发送前保护、配置白名单和状态元数据。
在安装 AstrBot 的环境执行 `python -m unittest discover -s . -p 'test_*.py'`。
浏览器验收应使用隔离桥接数据，避免试跑产生真实群发。
配套从绫的跨插件测试需同级源码，不能用 at_guard 的通过结果代替旧版从绫的验证。
